# 南风岛动态美术任务单

**版本：** DYN-01｜2026-10-12  
**适用工程：** `GodotProject`｜第一地图「南风岛」  
**任务目标：** 给当前已接入的海岛酒馆增加低成本、可循环的环境动态，并让中央的小葵有轻微呼吸/待机感。

## 1. 统一表现方向

- 暖色、轻松的 2.5D 微缩酒馆；背景是东南亚海岛木栈平台、蓝绿色海面、夕阳和烛光。
- 动态只服务于“场景活着”和“老板在营业”的感觉，不能抢走订单、客人和按钮的注意力。
- 不新增客人入场、行走、饮用、收钱或复杂分镜；第一地图不以动画素材数量作为内容卖点。
- 所有素材必须能被 Godot 的 `Sprite2D`、`AnimatedSprite2D` 或现有环境层直接使用；文字、金额和订单状态继续由引擎绘制。

## 2. 任务拆分

### DYN-01｜海面循环层（优先级 P0）

**最小交付：**

| 文件 | 规格 | 用途 |
|---|---|---|
| `Island_Southwind_WaterMask_v1.png` | 1672×941，RGBA，白色为可动海水、黑色为其他区域 | 局部海面着色器遮罩；必须与实际运行底图像素对齐 |
| `Island_Southwind_WaterFoam_v1.png` | 1672×941，RGBA，透明背景 | 可选的岸边柔和浪花层；只画海岸线附近，不覆盖桌椅和角色 |
| `Island_Southwind_WaterMask_v1.svg` | 可选，保留可编辑水域轮廓 | 若 PNG 遮罩难以维护，作为源文件保留，不替代运行 PNG |

**制作要求：**

- 使用工程实际运行版海岛底图作底，不使用聊天中的早期概念图重新猜坐标。
- 木栈道、桌位、中央花盘、吧台、岛屿和天空全部为黑色/透明保护区；海水边缘向内收 2–6 px，避免露底和抖动。
- 不要把波纹、白浪、文字或渐变烘焙进遮罩；遮罩只表达区域。
- 如果交付浪花层，浪花必须低对比、低透明，并在码头边缘断开，不能形成一圈白边。

### DYN-02｜烛光素材（优先级 P0）

**最小交付：**

| 文件 | 规格 | 用途 |
|---|---|---|
| `CandleFlame_Southwind_v1.png` | 256×256，RGBA，透明背景 | 桌灯火苗，可由程序做轻微缩放、位移和亮度变化 |
| `CandleGlow_Southwind_v1.png` | 512×512，RGBA，透明背景 | 桌灯/吊灯的柔光晕；边缘必须足够柔和 |
| `Island_Southwind_LightAnchors_v1.json` | UTF-8，记录逻辑画布锚点和相位 | 供开发对齐 7 张桌灯与 1 个吊灯 |

**锚点约定：**

- 继续使用现有 1600×900 逻辑画布和 `SCENE_AMBIENT_REQUIREMENTS.md` 中的灯位，不移动桌子、灯罩或背景。
- JSON 至少包含 `id`、`type`、`x`、`y`、`phase`、`scale`；`phase` 使用 0–1 归一化值。
- 火苗和光晕要分层；不要把完整桌子、灯罩、桌面或背景复制进素材。
- 交付一张叠回实际背景的灯位核对图，仅供验收，不放入运行目录。

### DYN-03｜小葵中央待机（优先级 P0）

小葵是双马尾、两侧向日葵发饰、黄色工作服的老板。她固定站在中央向日葵平台，动作只做“营业中的轻微待机”，不做走路或复杂服务动作。

**最小交付方案：3 帧固定画布循环**

| 文件 | 规格 | 说明 |
|---|---|---|
| `Sunny_Southwind_CenterIdle_00.png` | 512×512，RGBA | 自然站姿基准帧 |
| `Sunny_Southwind_CenterIdle_01.png` | 512×512，RGBA | 呼吸上行：身体/肩膀轻抬，双马尾略动 |
| `Sunny_Southwind_CenterIdle_02.png` | 512×512，RGBA | 呼吸回落：回到接近基准，不要夸张弯腰 |

**制作限制：**

- 三帧必须同尺寸、同脚底基准、同角色比例，不能自动紧裁；脚底位置误差不超过 1 px。
- 仅允许胸口/肩膀 1–2 px 的呼吸起伏、双马尾 1–2 px 的轻摆、衣摆和向日葵饰物的极小跟随变化。
- 不改变脸部识别、服装、手上道具和站位；不新增背面、八方向或入场帧。
- 透明背景，无阴影大底、无UI、无文字、无水印。若制作软件保留分层，至少保留身体、双马尾、发饰/衣摆三层源文件。
- 循环建议 1.2–1.8 秒，首尾姿态相近；不允许看起来像走路、跳跃、挥手或服务动作。

原稿和核对图先放：

```

确认后再复制到：

```

文件名仅使用英文、数字、下划线；不要在运行文件名中写中文、空格、版本说明或生成工具名。每项素材随附 `README.md`，记录来源、画布尺寸、透明方式、锚点和是否允许程序变形。

## 4. 通用验收标准

### 素材质量

- PNG 为真正 RGBA 透明，不是白底或棋盘格；边缘无白边、黑边、压缩杂色。
- 缩小到游戏实际显示尺寸后，海面边界、火苗、小葵轮廓仍清楚；素材不含文字和UI。
- 同一套素材的色温统一：海面偏青蓝，火苗偏暖黄，小葵保持当前金黄/棕色海岛工作服。

### 游戏表现

- 海面循环至少 6 秒无明显跳帧；波纹只在遮罩内，桌椅、平台、岛屿和角色不变形。
- 火苗每盏灯相位不同，亮度和位移轻微；不得爆闪、照白订单气泡或影响中文可读性。
- 小葵脚底固定，呼吸感能被注意到但不喧宾夺主；暂停、失焦、打烊和低动态设置时应可冻结。
- 16:9 及窗口缩放后，海面遮罩、灯光锚点和小葵站位仍与背景对齐。
- 提供至少一张“无动态底图 + 动态层叠加”的核对图；接入后由开发提供 10 秒录屏进行最终验收。

## 5. 本轮不做

- 不重画完整海岛背景，不拆 7 个客人动画，不做客人入场/离场/饮用动画。
- 不要求小葵 8 方向、走路、复杂服务、表情序列或 Spine 绑定。
- 不追加整套新UI；动态不应修改订单、收入、耐心、结算规则。
- 不将 Review 素材直接当作 Approved 或运行资源；先做静态素材验收，再接入 Godot。
