# 游戏方案 · 当前方向

> 2026-09-29引擎迁移：当前入口为GodotProject/project.godot，Godot 4.5.1标准版/GDScript。既有机制已迁移，前三天开放、Day4仍待开发。本文旧Unity路径和轮次为历史记录；当前配置在GodotProject/data，检查与边界见docs/Development/GODOT_MIGRATION.md。


## 定位

有趣的休闲经营与客人收集游戏。老板小葵喜欢旅行；客人有短小、有梗的人物小传，不以复杂文学故事推动进度。

主循环：闯关营业 → 获得金币 → 解锁客人图鉴 → 购买带轻加成的装饰 → 前往下一站。

地图顺序：东南亚海岛（南风岛）→ 北欧极光峡湾 → 希腊古城 → 星际。全游戏计划20个结局称号，第四地图触发；当前不开发后续地图和结局。

## 当前范围

当前为Godot 4.5.1标准版、GDScript / 原生Control UI。第一地图目标4天、每天120秒、7客位＋1出酒口、9位客人、3件装饰。旧实现前三天已迁移；G1同款互送与成品保留已实现并通过headless检查；收钱后清台尚待G2改造，不等于第一地图完成。

角色、场景和 UI 参考见 Art/Approved；当前运行素材位于 GodotProject/assets；UnityProject仅保留迁移对照。

小葵默认服装保留，各地图计划有对应服装，商店未来可购买。换装尚未列为本轮实现内容。

## 客人服务、对话与图鉴（2026-09-29 21:10 用户确认）

本节是当前玩法及客人素材范围，覆盖历史文档中冲突的表现要求。这里只更新设计与交接，不表示代码已经完成修改。引擎迁移和可玩版本以开发进度为准，上文Unity范围为原工程记录。

### 营业中的服务流程

客人入座 → 玩家点单 → 饮品自动排队制作 → 玩家在出酒口取杯 → 送达匹配客位 → 客人饮用后离场 → 桌位待收款 → 玩家收钱并自动清杯 → 座位释放。玩家一次手持一杯，杯子只按饮品种类匹配，不绑定访客，相同饮品可送给任意已点单且仍需要该饮品的客人；实际收款才计收入并按现行规则解锁图鉴。每张地图的客流、目标金额与特殊机制单独配置，既有南风岛规则见[MAP01_RULES.md](MAP01_RULES.md)。

| 环节 | 普通客人 | 惊喜客人 |
|---|---|---|
| 入座 | 展示座位Q版静态图 | 展示座位Q版静态图，可显示惊喜来访提示 |
| 点单 | 仅此环节显示点单对话形象与订单台词，不展开闲聊 | 可与老板进行角色专属对话，并完成点单 |
| 等待 | 订单、耐心条、倒计时、符号或短气泡 | 同样显示服务状态，剧情可配置专属对话 |
| 送餐/送饮品 | 在座位直接完成，用图标、数字、短文字反馈，不弹人物立绘对话 | 正常送达，可按剧情触发专属对话 |
| 收钱 | 在座位直接收款，显示金额，不弹人物立绘对话 | 收款自动清杯；收尾对话须在客人离场前完成 |
| 离场 | 喝完后静态图消失，桌上留钱和杯子，收钱后释放座位 | 同样处理，不要求专属离场动画 |

普通客人的再次询问属于订单回看，可复用同一张点单形象；不能重复创建订单或重置耐心。座位短气泡和机制提示不是剧情对话。惊喜客人不要求每次送达/收款都触发剧情，先写实际台词与触发条件，再决定需要哪些表情，不统一凑固定数量。

### 座位状态与计时

待点单、等待制作/送达、饮用、特殊事件复用同一张座位Q版图；客人离场后的待收款桌位不显示客人，只显示钱和用过的杯子，通过订单图标、计时条、数字和短文字区分。面向客人减慢耐心、错送惩罚、收款后清台、小费、连击、辅助模式与重试沿用既有地图规则。

点单界面与惊喜剧情对话沿用“弹窗暂停营业”：营业、所有客人耐心、制作、饮用、收款及特殊事件计时统一暂停；普通座位提示不暂停。关闭弹窗当帧隔离输入，防止误送杯或重复收钱。惊喜对话需支持推进/跳过，跳过文本不能跳过实际服务或触发重复奖励。该统一行为需在后续实现中核验。

### 特殊机制的轻量表现

普通客人已有机制保留，不额外增加闲聊或送达/收钱立绘弹窗。

| 客人 | 机制 | 素材与表现 |
|---|---|---|
| Bobo | 喝完赶着离开，桌位留款 | 金币与用过的杯子提示，收款后清台 |
| Coco | 行李占邻座 | 行李/占位标识 |
| Horn | 短暂显示订单，可再次询问 | 订单提示隐藏与点单回看 |
| Tank | 提醒摘呼吸器后再接单 | 两步均属点单，复用一张点单图与文字 |
| Gecko | 等待过久换一次空座 | 座位预告与静态图位置更新 |
| Mimi | 背对时伸手，需互动打断 | 座位预警、倒计时；打断后再正常服务 |
| SPF-8 | 双杯分次送达，送齐后收款 | 杯数进度，不新增双持或多腕动作 |
| Snowy | 限时送达降温 | 降温倒计时与短文字，不做融化动画 |

惊喜身份以所属地图人物表为准，Snowy等外形特殊的普通客人不自动变成惊喜客人。特殊饮品包含在既有地图菜单中，保留已确认杯型与美术。Jiwoo始终计同一人物；新地图首见收藏奖励仍为设计提案，需有效服务/收款与去重，不能因打开或重复对话直接发放。

### 客人美术：三种用途

| 用途 | 普通客人 | 惊喜客人 |
|---|---|---|
| 座位形象 | 1张场内Q版透明静态图 | 1张场内Q版透明静态图 |
| 点单/对话形象 | 1张固定点单形象，只用于点单及订单回看 | 基础对话形象＋实际剧本所需表情差分 |
| 客人图鉴详情立绘 | 必须有完整清晰的角色立绘 | 必须有完整清晰的角色立绘，默认展示基础表情 |

三种用途均需配置，但不等于每人必须重画三张原稿：点单形象可以从已确认的图鉴立绘适配或裁切；惊喜客人也可共用基础立绘。场内Q版与精细立绘分开配置，不把精细立绘默认当作合格座位图，也不能仅用小头像替代图鉴详情立绘。已有确认素材优先复用，保留物种、服装、道具与角色性格；缺图明确待制作/确认，不借用其他客人形象。

图鉴在完成有效收款后解锁，详情展示人物立绘、姓名/身份、小传及已定饮品信息；列表头像可由立绘裁切。未知客人保留未解锁表现，跨日保存收集进度。图鉴展示不算营业对话，不受“普通客人仅点单展示对话形象”的限制，也不需要新增图鉴动画。

不制作客人行走、八方向转身、入场分镜、逐帧饮用、送餐/收钱动作与专属离场动画。静态图淡入淡出、描边与位置变化由程序完成。普通客人不额外制作开心/不耐烦表情组；惊喜客人按实际剧情补表情。小葵已有确认转向与服务动作保留，本次不追加其动作数量。

### 开发交接与验收

- 普通客人只在点单/订单回看显示对话形象；送达、收钱、等待及特殊机制反馈在座位完成。
- 惊喜客人可与老板对话；剧情、表情、触发和重访处理按角色配置，不能重复下单或领奖。
- 对话统一暂停相关计时，关闭当帧不触发场内误操作。
- 座位Q版、对话形象、图鉴详情立绘分别检查，允许后两者复用原稿；每个已解锁客人的详情必须能显示正确立绘。
- 保留特殊机制、地图数值、现有素材和收集/重试规则。运行接入、图鉴展示与实际试玩尚待验收。

## 杯子与订单规则（2026-09-29 21:23 用户修正）

杯子只记录饮品种类，不绑定具体访客。玩家可把同种饮品送给任意已经点单、仍有该饮品未满足需求的在场客人，自行安排服务优先级。

- 送达只核对客人状态、饮品种类和剩余杯数；每次成功送达消耗一杯，只增加实际接收者的订单进度。不能因杯子由另一单触发制作而判错。
- 不匹配仍按既有错送规则处理，杯子保留。尚未正式接单、已经饮用或等待收钱的客人不接收额外杯子。
- SPF-8可接收任意两杯椰子水，分次送达、全部送齐后饮用，统一收款；部分送达不结算。
- Gecko换座只改变位置，订单需求与耐心继续；不存在“专属杯子跟随访客”的关系。
- 客人离开取消其未完成订单；已经做好的饮品（出酒口或手持中）保留，可交给其他点同款饮品的客人。SPF-8半单离场、Snowy降温超时也适用；已送出的杯子不回收、不转赠、不收半单款。
- 收入、小费、连击与图鉴归实际完成服务并收款的客人；按其饮品订单与送达时状态结算，不能沿用制作来源访客的奖励。
- 手持提示显示饮品名称；教学可建议一个可接收客位，但不能暗示只有该访客可以接收。Horn仍保持订单短时隐藏，不新增长期自动高亮泄露订单。
- 已完成饮品仅在本次营业内保留；打烊、重试或切换营业日按原规则清空，不跨日储存。

制作仍自动排队，一次手持一杯，不改为玩家主动选配方。离场或使用现成杯后，如何核减尚未开工的制作任务、处理已开工但未完成的饮品，以及无人需求时滞留杯的清理交互，仍需开发细化；不得沿用“离场按访客ID删除所有杯子”。这些边界不影响已确认的同款互送与成品保留规则。

本次为方案更新，未修改运行代码。原访客绑定实现、原清杯逻辑及其旧测试不代表最新设计，Godot迁移也需遵循本规则。

## 离场、收钱与清台（2026-09-29 21:25 用户确认）

客人喝完离场后，桌上留下待收款项和使用过的杯子，座位进入“待收钱/待清台”状态。玩家必须在该座位互动收钱；收款成功后自动清理桌上杯子，随后才释放座位给下一位客人。无需单独清洁按钮或客人离场动画。

- 正常服务流程改为：入座 → 点单 → 制作/取杯 → 按饮品种类送达 → 饮用 → 客人离场 → 桌位待收款 → 玩家收钱并自动清杯 → 空位。
- 撤销普通12秒/Bobo 6秒及辅助模式150%的收款倒计时。待收款桌位在营业中持续保留，不因超时自动释放；Bobo喝完赶着离开的角色特征保留，不再附带限时收款惩罚。
- 座位是否可入座按是否空闲判断，不能只看是否还有客人立绘。普通来客、Jiwoo优先候位、Gecko换座与Coco行李占位均不得占用待收款桌位。
- 客人离场后保留该次服务的待收金额、实际服务对象、饮品/杯数与结算所需结果。收款只执行一次，金币、小费、连击、图鉴仍在收款时结算；不因人物离开丢失归属。杯子无访客绑定不等于收款记录无归属。
- SPF-8两杯送齐才饮用离场，桌上两只使用过的杯子随整单收款一次清理。半单/未送达因耐心或事件超时离场，不虚构可收款项或算完整服务；若留有已用杯，处理边界待开发明确，不套用正常整单结算。
- “收钱后自动清杯”仅清理该桌已使用的杯子，不清除出酒口和手持的未送出饮品；这些成品仍可按种类送给其他客人。
- 打烊只结算已收收入。仍未收的钱不自动计入钱包；下一局/重试按原规则重置当局桌位与杯子，不把未收桌位带入下一天。

界面需清晰区分有人待服务、无人但待收钱、完全空闲三种状态；待收款桌位显示金币与用过的杯子，允许直接点击收钱，不弹普通客人对话。辅助模式保留耐心、Mimi预警与Snowy期限调整，删除已经无对象的收款时限加成。

以上是当前设计要求，运行状态机、入座判断、收款后清杯与相关检查尚待修改；不新增清洁小游戏或杯子清洗动画。
