## 直接使用

每件提供 PNG + AtlasTexture `.tres` + Node2D/Sprite2D `.tscn`。将 `.tscn` 实例拖入场景，根节点是定位锚点；TextureRect可直接使用 `.tres`。所有资源路径为 `res://assets/Decor_SW_*_v2.*`，放在现有GodotProject/assets即可。`.import`由Godot4.5.1实际导入生成，随PNG提交；不提交.godot缓存。

| 文件前缀 | 升级位 | 分层及锚点 |
|---|---|---|
| Decor_SW_Counter | 吧台 | 主体含固定花叶、器具与灯架，不含吊灯；底部中心 |
| Decor_SW_Chair | 座椅 | 一把单独藤椅，单视角；底部中心 |
| Decor_SW_TableLamp | 灯具 | 独立桌灯；底部中心 |
| Decor_SW_HangingLamp | 灯具 | 独立吊灯；顶部中心，挂到吧台灯架 |
| Decor_SW_Railing | 栏杆 | 两跨三柱模块；底部中心 |
| Decor_SW_Table | 客桌 | 无灯、无植物的独立桌子；底部中心 |
| Decor_SW_Deck | 地板 | 整个平台，保留向日葵中心；画布中心 |

`Decor_SW_manifest_v2.json`记录尺寸、Alpha有效范围、SHA256、裁切区域、锚点、预览宽度。Atlas只去除外围全透明区域，不改变已确认图像。场景里的宽度是预览建议值，**不是最终摆位或原背景覆盖坐标**。

## 独立购买与摆放

六个升级位分别保存，桌灯/吊灯共享lighting购买状态；椅子和桌子购买一次后更新该地图所有对应实例，不能逐客重复购买或加成。吧台购买不自动改变灯具，地板购买不自动改变栏杆/家具。无碰撞或输入脚本，不新增交互区域。桌灯放在桌面上层，客桌在客人下半身前方，椅子在人物后方；前景栏杆与吧台遮挡需按当前场景检查，不使用统一z值覆盖全部客人。

原Island_Background已烘焙家具、栏杆、地板，不能简单加新图而把旧图留在底下。接入前需拆出基础层/修补底图，并保留旧外观；也不能整图换装，否则六件无法独立购买。当前素材不包含处理完成的干净海面底图和原版独立物件。

## 验证与边界

- 七张PNG均解码通过，RGBA且Alpha范围0–255；SHA256在清单中。
- Godot4.5.1 headless实际导入，以及七张AtlasTexture、七个PackedScene加载/实例化检查通过。
- 这是可导入的独立素材交付，不代表主游戏已挂载或视觉验收通过；未修改主场景/商店/存档代码。
- Chair只有当前三分之四视角，Railing只有当前模块视角；禁止将屏幕旋转或水平拉伸冒充透视朝向。其它座位/边段需要对应视角适配。
- Deck与部分物件非零Alpha接近画布边缘，必须检查贴边轮廓；不承诺逐像素对应原背景。
- 灯图已有静态亮芯，现有光晕可调制亮度。若需火苗独立摇摆，应另拆无火灯体/火苗层，不能在已有火苗上叠两个火苗。暂停与低动态开关沿用原实现。
- 吧台去灯及独立吊灯是确认原稿的拆分派生，需在场景里复核比例；原始带灯确认图保存在Art/Decor_SW_Counter_ApprovedReference_v2.png。
